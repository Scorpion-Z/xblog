    title: "发出去的是纸条，收到的仍应是 IP 数据包。"
    text: "发送端将原始字节编码为十六进制文本，打印、卷起并交给信鸽。接收端取下纸条，扫描、识别，再还原出字节。现实中还需要程序衔接网络接口，鸽子不会自己识别 IP 地址。"

  - kicker: "03 / TCP/IP 的分层"
    title: "更换运输方式，不代表要重写整个互联网。"
    text: "TCP/IP 把应用、传输、网际和网络接口等职责分开。IP 处理寻址和数据报，底层负责让字节经过链路传递。光纤、无线电或特制的信鸽链路，理论上都需要满足相应的承载接口要求。"
    detail: "分层降低了各部分的耦合，但没有消除底层链路的约束。"

    title: "它的 MTU，写的是 256 毫克。"

  - kicker: "06 / Ping 通，不代表网页可用"
    title: "如果换成 TCP，等一次握手就够喝很多杯咖啡了。"
    text: "Ping 使用 ICMP，并不需要 TCP 三次握手。传统 TCP 建连需要 SYN、SYN+ACK 和 ACK；在超长往返延迟的链路上，超时与重传机制会严重影响应用体验。即便能传递 IP 数据，也未必适合浏览网页、视频会议或远程登录。"

    title: "真正值得记住的，是数据可以先被保存，再继续前进。"
    text: "当端到端链路经常中断，传统即时通信就会遇到困难。容迟网络（DTN）采用存储、携带、转发等思路，让消息在新的通信机会出现后继续传递。RFC 1149 不是现代 DTN 协议，但这个故事能帮助我们理解问题的来由。"
